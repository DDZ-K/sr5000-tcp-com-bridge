# SR-5000 TCP → COM 桥接 v1.1.2-field.1

本版从已经现场确认回车有效的 TCP v1.0.1 扩展，不替换旧工具或旧配置。用于现场试用，不是生产验收版。

## 你的连接方式
扫码枪 → TCP → SR5000TcpComBridge.exe → 桥接端 COM → 虚拟串口对 → 软件端 COM → 本机另一软件。

两程序必须打开同一虚拟串口对的不同端点。举例只有在库存确认 COM7/COM8 是一对且方向正确时，才可让工具开 COM8，目标软件开 COM7；这些号码不是默认值。没有一对虚拟端口时，单独选择某个物理COM口不能让本机另一程序直接收到数据。本版只支持经过核验的 com0com 配对；其他虚拟串口产品暂未适配。

## 首次使用（Win7 x64试用）
1. 手动退出旧TCP调试工具、旧桥接和会占用扫码枪连接的网络助手，保留旧目录。将本包解压到一个新、可写的目录，打开 SR5000TcpComBridge.exe。不要直接在ZIP里运行。
2. 可以先把旧TCP v1.0.1目录的 tcp.ini 复制进新目录，保留IP、两个设备端口、ASCII/HEX内容与按键选择。不会自动连接或自动触发。后台按键每次打开默认关闭。
3. 已有COM7/COM8等端口时，不要重复安装驱动。先核对为同一com0com串口对。在界面分别填写/选择“桥接端 COM”和“软件端 COM”，点击“创建 / 配对设置”核验；若方向参数缺失，工具会先确认再请求管理员授权，不修改号码。
4. 没有com0com时，由管理员阅读 drivers/win7-x64/Win7先看.txt，手动安装其中的 Win7 x64 签名安装器。本程序不会自动运行安装器。安装后刷新COM；新建配对只能用两个不存在且未被系统保留的号码。点击“创建 / 配对设置”后确认UAC。完成前不能重复创建或重连。若驱动报代码52/签名错误，停止并反馈，不关闭签名校验、安全启动或启用测试模式。
5. 目标软件设置“软件端 COM”并打开；工具设置另一端，勾选“启用 TCP → 串口转发”。波特率、数据位、校验、停止位与目标软件一致。界面初始9600/8/无校验/1只是可编辑起点，不代表目标软件要求。
6. 保持你已验证有效的扫码枪IP、接收设备端口、发送设备端口和触发指令。两个端口相同会共用一条双向TCP连接。只有确认该流全部内容可交给目标软件时才勾选“共用连接原样转发（含应答）”；未确认禁止开启共享流串口转发。此确认每次启动需重新勾选。
7. 点“连接 / 保存并重连”，确认接收TCP、发送TCP、桥接COM已打开及软件端状态。后台触发勾选Enter后切到目标软件/记事本。扫码收到后应先看“COM 转发”日志、写COM字节数，再确认目标软件实际显示了同一内容。

## 行为
- 保留v1.0.1的40字节Win64键盘包修复；不吞原按键，长按不重复。工具自己前台时不自动触发。不要求选择目标EXE。
- 一直接收，不需要先按键、不限制一键一个码。收到扫码端口的原字节就转发，不重新编码，不添加/删除CR、LF、NUL或其他字节。TCP拆包/粘包不等于完整条码；目标软件按自身协议处理字节流。
- 不同设备端口时，发送连接的命令应答只显示，不转COM；发送连接失败不阻断仍正常的扫码端口接收/转发。
- 同端口无法凭空识别命令应答；确认后整个接收流都会转COM，包含可能的OK/错误响应。真实协议未确认前不要用于生产。不会凭固定字符串猜测过滤条码。
- 启用串口时，软件端没打开、配对错误或串口写故障会阻止新触发。发生串口故障后继续TCP接收显示，但停止COM转发且不补发；核对实物后手动断开/重连。
- 没有自动TCP重连、旧触发重放或旧码缓存补发。部分写入或取消不确定时可能有部分/延迟数据已经到达，请人工核对；不能保证跨设备/驱动/目标软件的exactly-once。
- 配对核验每次手动连接重新执行。已存在/离线保留的COM不覆盖；设置进程超时保留状态，不强杀安装。配对设置涉及管理员明确确认；读取库存若报740/5，可让管理员核实后运行工具，不自动提权。
- 日志在 logs/tcp.log，约2MiB轮转一份，显示队列有上限。不新增自启、计划任务或Windows服务。无反向 COM → TCP 命令桥接；本次需求是扫码内容单向送目标软件。

## 配对设置与回退
- 包装/软件端：EmuOverrun=yes；桥接端：dsr=ropen,EmuBR=yes。DSR状态依赖驱动映射，只能说明驱动报告对端打开，不代表目标软件已收到/已处理。
- 修改已有配对前记录原有参数；如要恢复，用com0com Setup恢复记录的值，不删除原有端口。只删除你本次新建且确认无人使用的一对；驱动卸载使用Windows程序卸载界面，先停止两端。
- 工具回退：退出新版，再打开保留的TCP v1.0.1旧目录。新版与旧版不可同时争抢扫码枪连接；旧TCP版不带串口转发。

## 包内驱动与兼容边界
包含 drivers/win7-x64 下的原样 Win7 x64 com0com v3.0.0.0签名安装器、完整上游源码ZIP、GPL许可和来源/哈希记录。不是Win7 32位安装包，不承诺Win10/11可加载此Win7驱动。Win10/11须另用适配并获批的驱动环境；不得因EXE能启动就认为内核驱动兼容。

## v1.1.1-field.1：管理员启动后仍显示“Windows错误0”
- 现场截图实际是错误0，后面的740/5只是旧版固定提示，并不能证明仍需提权。旧版把ParseError/NonzeroExit/Timeout等仅显示win32Error，掩盖真实失败阶段。现场setupc原始输出未取得，不能断言是哪个具体解析异常。
- 本版正常连接优先只读系统已有COM设备的DOS映射、com0com服务参数；若为COM#系统分配别名，再以SetupAPI的实际设备对象与PortName交叉核验。不是跳过配对，不执行安装器，不重命名COM，不改驱动参数。
- CNCA/CNCB配对来自驱动PDO命名，寄存参数位置和dsr=ropen常量来自包内上游3.0.0.0源码include/com0com.h、sys/adddev.c、setup/params.cpp。只接受同一编号的A/B端；两个相邻COM不自动算一对。
- 正常核验成功时不启动setupc；如果系统证据不可用，才尝试原只读列表，报错明确区分启动、退出码、解析、超时并保留有限原始输出。只有实际Windows码为740/5才提示权限。
- “创建/配对设置”对已有端口也使用同一套只读系统证据；修改映射仍需用户确认及系统授权，不自动修改。如果提示同对但参数不符，请先关闭目标软件串口，断开桥接，再点击配对设置，核验后重新打开目标软件串口、连接桥接。
- 更新：退出旧EXE，新目录解压，复制原tcp.ini保留IP/端口/指令/COM；不要重装驱动。现场这一对是桥接COM8、软件COM7。目标软件/串口助手开COM7；桥接工具开COM8；参数一致。后台按键需重新勾选。
- 新增使用临时HKCU注册表的系统参数读取回归：真实Reg读写、COM#别名必须有系统设备证据、错误端点/设备目标/数据类型/DSR取反拒绝、默认参数不冒充安全映射、清理测试键。该测试不创建/修改HKLM驱动配置，不代表现场真驱动验收。

## v1.1.2-field.1：未分配COM#不再阻挡已选配对
现场日志截图明确显示：CNCA2/CNCB2尚无RealPortName，但CNCA1=COM7、CNCB1=COM8都有明确系统分配号码，COM7端EmuOverrun=yes，COM8端EmuBR=yes且dsr=ropen。旧解析器在另一组未分配COM#上整体失败，导致已选配对也无法使用。
本版仅修正这一解析：保留未分配端点的CNCA/CNCB标识，不给它猜COM号；已选COM7/COM8仍须验证同一对及信号配置。非法RealPortName、同名COM、重复端点与跨组选择继续拒绝。原系统读取错误13的具体注册表字段尚未取得，未假称该原生格式问题已查明；完整CLI列表现在可以作为备用证据正确解析。
按截图可见配置转录成隔离测试：其他未分配对+COM9/10+COM7/8混合列表，旧版红灯失败，修复后解析及真实TCP工作线程→明确假串口文件原字节转发通过，触发回包、原GUI/按键和故障回归通过。不是产线真实串口验收。
升级：退出旧工具，新目录解压，拷贝旧tcp.ini保留全部已保存参数。打开标题v1.1.2-field.1的SR5000TcpComBridge.exe，保持桥接COM8/软件COM7与115200/8/无校验/1；软件/串口助手打开COM7后再连接桥接。不要删除CNCA2/CNCB2，不重新创建配对，不重装驱动。勾选共用连接原样转发及后台Enter（这些安全勾选按本版逻辑每次启动需确认）。
