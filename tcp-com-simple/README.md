# SR-5000 扫码串口桥接 v1.2.1 精简版

用户已明确现场使用扫码枪单一TCP服务端监听端口，本程序作为客户端在同一条连接收发。本版只显示一个“通讯端口”，不把客户端系统分配的本地端口当作配置。服务器/客户端角色本身并不保证所有设备只用一个监听端口；这里只实现用户已经确认的现场拓扑。

## 改动
- 一个通讯端口，同时用于发送触发与接收扫码；状态合并为TCP连接和串口转发两卡。
- 删除主界面“共用连接原样转发”勾选及启动设置中的共享确认项。启用串口时，接收的数据默认原字节转到已核验串口，包含可能的设备命令应答；不擅自猜测过滤、不加删换行。
- 博世Logo改为黑白图形标，没有BOSCH字样；主窗口及程序图标均更新，资源嵌入EXE。
- 保留现有COM端点选择、按键触发、ASCII/HEX转换、一次启动连接/托盘和故障不重放逻辑。
- 通信引擎和串口/编解码/配对模块逐段/逐文件保持与此前已验证版本一致。仅操作界面、配置入口固定为一条双向TCP，不重新设计通信实现。

## 升级
1. 退出旧桥接及其托盘实例，保留旧目录。解压新包到新目录。
2. 复制旧tcp.ini保留现场IP、端口、指令、COM和串口参数。旧ReceivePort与SendPort相同时自动显示成一个通讯端口；若旧两端口不相同则留空，必须人工确认，不猜选其中之一。新的CommunicationPort键优先；保存时也写入相等的两个旧键，便于旧版回退。
3. 若以前配置过启动选项，可复制startup.ini保留自动连接、后台键、托盘和延迟设置；旧Shared/Signature字段不再控制连接。打开SR5000TcpComBridge.exe，确认标题v1.2.1。
4. 工具打开“桥接端”COM，目标软件打开同一对的“软件端”COM。例如现场已验证桥接COM8、软件COM7，保持两端参数一致。不要重新安装驱动、创建/删除已可用配对。
5. 点“保存并连接”，按已选触发键使用。串口转发的“启用转发”控制是否把收到的内容写入COM，并非安装驱动开关。

## 自启动
右上角“启动设置”可选当前用户登录Windows后自启动、启动时尝试连接一次、恢复后台键、收起到托盘和延迟秒数。开启/关闭都必须点击应用；不会因为打开本工具自动注册。更换到新目录后重新应用启动设置，若原启动项指向旧目录，会要求明确确认替换，不能同时运行两个版本。
不是登录前服务，不自动提权，不在开机时自动发送触发，不重放旧码，不默认循环重连。最小化收起托盘，点X仍退出。现场Windows重启和驱动权限时序须现场验收。

## 验证
- 严格/W4 /WX构建、NDEBUG原TCP/COM模拟/40字节键盘GUI回归通过。
- 新增真实GUI断言：不存在第二端口控件、共用流复选框、第二TCP状态；启动设置也不存在共享确认项。
- 通讯端口新旧配置迁移、旧端口不相等拒绝猜测、配置保存恢复、单TCP连接双向字节和串口转发、启动不依赖旧共享确认均通过。
- 仅临时HKCU测试键验证自启动注册回读/删除，测试前后真实Windows Run值不改变；不在开发电脑实际开启自启动。
- 最终交付EXE实际启动并截图核对；截图不是效果图。真实扫码枪/内核虚拟串口/目标软件与工位重启仍需现场验证，本机模拟串口不等于真实驱动验收。
