# SR-5000 TCP → 虚拟 COM 桥接（Win7/10/11 x64）

## 用户可见行为
- 扫码枪 IP、接收端口、触发发送端口可编辑；若两端口相同，只建立**一条**双向 TCP 连接，收到的字节原样转给包装软件 COM。若两端口不同，建立数据/命令两条连接。两端口相同且扫码枪把指令应答发在同一连接时，应答也会被转发；在现场确认协议前不要用于生产。程序不会猜测设备端口。
- 「触发内容」支持纯文字、`hex:4C 4F 4E 0D` 和 `4C 4F 4E 0D`（后两者发送四个字节，不另加 CR/LF）。触发按键为 Enter、Space 或 F1–F12。**暂时移除包装程序 EXE 前台限制**：任何前台程序下的选定按键均可能触发（桥接配置窗口自身除外）；需保持包装软件串口端已打开且 TCP 在线，避免其他程序误触发，不要在产线随意按键。不会吞掉原键。没有按键时数据接收仍持续进行。
- TCP 中断、端口关闭、部分串口写入等模糊故障后**不自动重发业务数据**；严重故障需核对实物并人工解除。绿灯仅证明连接，不代表扫码成功。

## 虚拟串口交付边界
- Windows 用户态 EXE **不能自行生成 COM 设备**。本版有「创建虚拟串口对」按钮：若系统已安装 com0com 且 `setupc.exe` 在标准安装目录，操作员在非生产状态输入包装软件/桥接端的两只**未占用** COM，确认 UAC，程序调用 `setupc install` 创建串口对；会先拒绝任何已存在端口，不覆盖现有 COM。缺少驱动时清楚提示，不会声称创建成功。驱动不在 GitHub 包内；必须由 IT/管理员安装与目标 Win7/10/11 版本、内核签名/安全策略相容的合法签名驱动，不关闭驱动签名或安全启动。此版尚未在三种 OS 真机和驱动上验收，不能保证一份驱动跨版本通用。
- 用户提供的 Win7 设备管理器显示已有 **com0com COM7 与 COM8**，不是 COM19。先用管理员命令提示符运行 `setupc list` 核对 COM7/COM8 确实为一对，再把包装软件端填 COM7、桥接端填 COM8（仅在现场核对方向和占用后）；**切勿先安装另一对或直接覆盖既有端口**。Win11 截图未见“端口（COM 和 LPT）”，先由管理员安装合适驱动或检查设备管理器隐藏设备。两个 OS 的截图不是同一电脑。
- 包装软件只打开包装软件端，桥接程序只打开桥接端；先验证驱动的 `dsr=ropen` 与对端开启检测、`EmuOverrun=yes`，在串口终端实测端口关闭/重开不残留旧码。已有串口对不一定使用了这些设置，未验证之前**程序会因对端状态异常而拒绝触发**。软件不会自动修改已有串口对。
- 若创建按钮缺少驱动或安装失败，先看设备管理器/驱动签名和退出码，不要反复点击创建。`create_port_pair.bat` 是管理员手动后备脚本，也必须先安装合适驱动并核对空闲端口。

## 部署
1. 把整个便携包复制到目标电脑固定目录。运行 `SR5000Bridge-v2.exe`；保留 `bridge.ini` 在 EXE 同目录。旧版本托盘实例先人工退出，单实例互斥不会让新旧版同时运行。
2. 现场确认两端口/IP/触发 HEX，配置包装软件端 COM 与桥接端 COM（不同号码），如缺少驱动请先让 IT 安装。选择旧有的一对时不要点击创建，核对 `setupc list` 后直接填两端并保存重连；全新创建则先在界面填两个空闲号码，点击「创建虚拟串口对」，UAC 授权完成并验证设备管理器后再保存。
3. 用串口终端在包装软件端确认主动扫码字节无按键也能收，发送测试指令应只在所选按键按下时触发；确认同端口时任何设备应答不会污染包装码；再做包装软件/扫码枪/Win7、Win10、Win11 各自现场验收。
4. 仅在现场验收后点击「安装登录自启」。这只是当前用户登录后启动，不是无人登录的 Windows 服务。虚拟串口驱动安装/创建需管理员，软件启动不自动执行此操作。

## 编译与测试
`bridge.cpp` 为 Win32/C++ 源码，`test.cpp` 含同端口与双端口回环、HEX/文字解析、数据原样转发测试。使用 MSVC x64、静态 CRT、Windows 7 子系统编译。此类本机模拟**不等于** Win7/10/11 驱动与生产设备验证。
