# SR-5000 TCP → 虚拟 COM 桥接（Win7/10/11 x64）

> **v2.1.0-field.1 现场试用版：仍需预装合适的已签名 com0com 驱动。** 目前没有能对 Win7/10/11 无条件自动安装驱动并完成现场验收的一体包；不能将此包视为免驱动、三系统已验收的生产成品。

## 用户可见行为
- 扫码枪 IP、接收端口、触发发送端口可编辑；若两端口相同，只建立**一条**双向 TCP 连接，收到的字节原样转给包装软件 COM。若两端口不同，建立数据/命令两条连接。两端口相同且扫码枪把指令应答发在同一连接时，应答也会被转发；在现场确认协议前不要用于生产。程序不会猜测设备端口。
- **发送编码由 ASCII／HEX 下拉框明确选择，不再根据内容猜测。** ASCII 输入 `L`，切换 HEX 自动显示 `4C`；反向也自动转换。ASCII `4C` 是两个字符，切到 HEX 为 `34 43`。HEX 可填空格字节或连续完整字节；无效/半字节输入不允许切换，原内容与模式保留。支持 1–64 字节，不自动追加 CR/LF。
- ASCII 中控制字节可逆显示为 `\r`（CR）、`\n`（LF）、`\t`（TAB）、`\0`（NUL）、`\xNN`（其他字节）；字面反斜杠输入 `\\`。例如 HEX `4C 4F 4E 0D` 切到 ASCII 为 `LON\r`，再切回来字节不变。ASCII 不支持直接输入中文；切换编码只转换未保存界面，不会发指令，也不会自动更改运行中的发送配置。确认内容后点“保存配置并重连”。
- 模式与内容在 `bridge.ini` 的 `TriggerEncoding`、`TriggerText` 中保存；兼容旧版 `TriggerHex`，升级时按旧语义解析再显示为 HEX，避免偷偷改变原发送字节。保存会保留 ASCII 首尾空格和引号。
- 触发按键为 Enter、Space 或 F1–F12。**暂时移除包装程序 EXE 前台限制**：任何其他前台程序下的选定按键均可能触发（桥接配置窗口自身除外）；需保持包装软件串口端已打开且 TCP 在线，避免其他程序误触发。不会吞掉原键；不按键时仍持续接收扫码。
- TCP 中断、端口关闭、部分串口写入等模糊故障后**不自动重发业务数据**；严重故障需核对实物并人工解除。绿灯仅证明连接，不代表扫码成功。

## 虚拟串口交付边界
- 「创建虚拟串口对」调用管理员已安装的 com0com，检查两个名称格式、系统 COM 保留表、当前端口和 com0com 库存。已有/离线保留端口不会覆盖。用户确认后才停止离线重试，系统 UAC 授权安装；安装异步运行，保留进程句柄，超时也不允许重复创建。`create_port_pair.bat` 仅打开同目录 GUI，忽略全部参数，不再把参数直接拼到管理员命令行。
- **每次启动、保存重连或初始连接失败后的重试，真实工作线程重新读取 `setupc --silent --detail-prms list` 库存**，检查所填两端是否同一 CNCA/CNCB 编号且安全映射匹配。失败就停止，不以“端口存在”或单独 DSR 信号冒充配对已验证。setupc 缺少权限时明确返回错误，请由管理员核实后运行；不自动提权做只读检查。从Windows已知文件夹API解析标准安装目录，不读取环境变量ProgramFiles/PATH；检查目录/EXE非重解析点、管理员所有且普通用户无写权限，不执行用户可写位置的伪setupc。
- 仍需 IT/管理员从可信来源安装适用于目标系统、满足签名/安全策略的驱动。包内无 SYS/INF/CAT，不会关闭驱动签名、安全启动或要求测试模式。Win7/10/11 实机驱动尚未验收，EXE 的 x64/子系统 6.1 只说明构建目标，不能作为全兼容证明。
- 用户提供的 Win7 设备管理器显示已有 **com0com COM7 与 COM8**，不是 COM19。先用管理员命令提示符运行 `setupc list` 核对 COM7/COM8 确实为一对，再把包装软件端填 COM7、桥接端填 COM8（仅在现场核对方向和占用后）；**切勿先安装另一对或直接覆盖既有端口**。Win11 截图未见“端口（COM 和 LPT）”，先由管理员安装合适驱动或检查设备管理器隐藏设备。两个 OS 的截图不是同一电脑。
- 包装软件只打开包装软件端，桥接程序只打开桥接端；先验证驱动的 `dsr=ropen` 与对端开启检测、`EmuOverrun=yes`，在串口终端实测端口关闭/重开不残留旧码。已有串口对不一定使用了这些设置，未验证之前**程序会因对端状态异常而拒绝触发**。软件不会自动修改已有串口对；映射不符会拒绝连接，需管理员核对后调整。
- 若创建按钮缺少驱动或安装失败，先看设备管理器/驱动签名和退出码，不要反复点击创建。`create_port_pair.bat` 仅启动 GUI；不会自动安装驱动、接受 COM 参数或执行提权命令。

## 部署
1. 把整个便携包复制到目标电脑固定目录。运行 `SR5000Bridge-v2.1.exe`；保留 `bridge.ini` 在 EXE 同目录。旧版本托盘实例先人工退出，单实例互斥不会让新旧版同时运行。
2. 现场确认两端口/IP/触发 HEX，配置包装软件端 COM 与桥接端 COM（不同号码），如缺少驱动请先让 IT 安装。选择旧有的一对时不要点击创建，核对 `setupc list` 后直接填两端并保存重连；全新创建则先在界面填两个空闲号码，点击「创建虚拟串口对」，UAC 授权完成并验证设备管理器后再保存。
3. 用串口终端在包装软件端确认主动扫码字节无按键也能收，发送测试指令应只在所选按键按下时触发；确认同端口时任何设备应答不会污染包装码；再做包装软件/扫码枪/Win7、Win10、Win11 各自现场验收。
4. 仅在现场验收后点击「安装登录自启」。这只是当前用户登录后启动，不是无人登录的 Windows 服务。虚拟串口驱动安装/创建需管理员，软件启动不自动执行此操作。

## 编译与测试
`bridge.cpp` 为 Win32/C++ 源码，`test.cpp` 含同端口与双端口回环、HEX/文字解析、数据原样转发测试。使用 MSVC x64、静态 CRT、Windows 7 子系统编译。此类本机模拟**不等于** Win7/10/11 驱动与生产设备验证。

- 组合框真实切换事件、`L ↔ 4C`、`LON\r`、全部 256 个字节往返、空内容切换、非法 HEX 回退、ASCII 首尾空格/引号保存及重新加载均通过。
- 本机 TCP 接收端实测 ASCII `LON\r` 和 HEX `4C 4F 4E 0D` 均为恰好四字节，无多余换行。串口配置明确关闭 XON/XOFF、NUL 丢弃等继承设置。

## 安全修复与边界
- 命令连接失败/断开只锁定触发，已建立的扫码通道继续接收；不会自动补发命令。数据通道断线/串口对端关闭/写入不明确则锁定，需人工核对后重连。请注意只代表本软件不重放，设备/驱动/包装软件各自的缓存仍需现场测试。
- 输入按采集时间、250ms 有效期和连接/配置代次处理，断线重连丢弃旧按键。没有固定300ms节流；键盘长按自动重复仍抑制。操作过快或UI延迟的过期触发会丢弃，不排队到以后偷偷发送。
- 配置先写临时副本、完整校验回读、刷盘后同卷替换；失败保留原配置且桥接停止，不会以旧/混合参数继续运行。
- 串口写取消超过时限时保留未完成 I/O 的句柄、OVERLAPPED 和缓冲区，锁定写入并告警，避免无限等或释放还被驱动使用的内存。**故障驱动仍可能晚完成先前写入，因此必须人工核对实物，不能承诺 exactly-once。**
- 同端口共享模式保留原始字节流，不捏造应答过滤规则：若扫码枪同连接返回 `OK` 等指令响应，也会转入包装软件。真实协议未确认前只用于测试，生产需完成命令应答/扫码分流验证；不能宣称全功能已投产。
