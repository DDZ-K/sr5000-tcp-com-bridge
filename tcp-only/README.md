# SR-5000 扫码枪 TCP 调试版 v1.0.1（不使用 COM）

本次只验证“触发扫码枪”和“接收显示”，不读写 COM、不调用 com0com、不依赖包装软件，不安装驱动或自启。旧桥接版目录、配置和发布包保持不变。

## 最少操作
1. 若旧桥接程序、网络调试助手正在连接这台扫码枪，请先由你手动断开它们，避免扫码枪连接数限制；不要同时开多个客户端争抢数据。
2. 双击 `SR5000TcpTester.exe`。填写扫码枪真实 IPv4、扫码接收端口、触发发送端口。两个端口相同则一条 TCP 双向连接，不同则两条独立连接。都是扫码枪的服务端端口，不是电脑临时本地端口。
3. 选 ASCII 或 HEX，填真实触发指令。ASCII 输入 L，切换 HEX 自动变 4C；HEX 4C 4F 4E 0D 可转换为 ASCII 的 LON\r。程序不自动追加 CR/LF。切换只改变显示，不发送。ASCII \r=回车、\n=换行、\\=反斜杠、\xNN=字节。
4. 点击“连接 / 保存并重连”，看接收/发送状态和红绿指示；再点击“发送触发”。TCP写成功只说明本机交给网络，不证明设备执行。
5. 下方接收区显示时间、来源、HEX、ASCII；不按触发也持续接收。独立命令端口的应答会标为“RX 命令应答”；共用端口的所有字节都标“RX 共用连接”，不擅自猜测哪段是条码或应答。TCP可能拆包/粘包，一条显示不一定是完整条码。
6. 先用按钮测试。若要后台按键触发，勾选“启用后台按键触发”，选 Enter / Space / F1-F12。其他程序前台也会触发；本工具自己窗口前台不触发、不吞按键。默认不勾选，避免现场误触发。
7. 断线或发送失败后不自动补发旧触发；接收/发送若是独立连接，一个失败不阻塞另一个。需恢复时手动重新连接。关闭窗口即完全退出，不偷偷留托盘，也不注册自启。

## 配置和日志
`tcp.ini` 与 EXE 同目录；点击连接保存 IP、端口、编码、指令、按键，不需管理员。配置保存失败不改变现有连接。日志 `logs/tcp.log` 与上一份 `tcp.previous.log` 各约2MB滚动，显示队列/文本有上限。高流量可能丢弃旧显示记录并提示，不能当作零丢失采集仪器。

## 已验证 / 待现场试
开发机 /W4 /WX x64 静态运行库、最低子系统6.1构建；真实TCP loopback+真实工作线程/GUI测试：相同端口只有一条连接、双端口、无按键主动接收、二进制0/FF/回车换行、ASCII/HEX精确发送且不补结束符、命令通道断开数据持续收、断线不重连不重放、256字节模式往返、配置文件被锁时保存失败保护。

不需要 COM 驱动即可测试。Win7 64位为构建目标；真实 Win7/扫码枪协议仍由现场验证，不预先宣称扫码成功。带到现场先发一张连接状态和日志，我再据真实应答调整。

## v1.0.1 后台回车修复
- 修复：64位 RAWINPUT 包含鼠标等类型的联合体，sizeof(RAWINPUT)=48，但合法键盘输入仅需要40字节；旧版把真实键盘报文拒绝，所以按钮可以发送、后台回车不发送。这是程序错误，不是现场IP/端口或操作者设置问题。
- 接收键盘报文改为按 RAWINPUTHEADER+RAWKEYBOARD 实际长度检查，并验证类型与dwSize；消息循环明确派发WM_INPUT。
- 勾选后台触发时显示开启日志；有效后台按键显示“已捕获后台 Enter”，随后应看到TX；监听注册成功/失败也带明确日志。自己配置窗口前台时日志说明不发送。
- 本机回归用精确40字节键盘数据包调用实际解析入口，经真实GUI设置/真实TCP工作线程发出4字节指令；验证长按重复抑制、抬起再按、过期输入和关闭勾选不发送。仍未在产线Win7实机按键验收，交付给你现场试。
- 升级：退出旧TCP调试窗口，解压本包到新目录；可从旧目录复制tcp.ini到新目录保留设置，打开标题含v1.0.1的SR5000TcpTester.exe。勾选后台按键，切记事本再按Enter，不用修改扫码枪参数。
